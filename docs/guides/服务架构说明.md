# 服务架构说明

## 📋 为什么 Docker Compose 启动后还要用 Python 启动服务？

### 当前架构设计

项目采用**混合架构**，将服务分为两类：

#### 1. **Docker 中的服务（基础设施）**
- ✅ **MySQL**（数据库）- 端口 3306
- ✅ **Redis**（缓存）- 端口 6379
- ⚙️ **Celery Worker**（可选，默认本地运行）
- ⚙️ **Celery Beat**（可选，默认本地运行）
- ⚙️ **Flower**（可选，Celery 监控）- 端口 5555

#### 2. **本地 Conda 环境中的服务（应用服务）**
- ✅ **Flask API**（后端 API）- 端口 5000
- ✅ **WebSocket**（实时通信）- 端口 8765
- ✅ **Celery Worker**（默认本地运行，便于调试）
- ✅ **Celery Beat**（默认本地运行，便于调试）
- ✅ **前端 Vue3**（前端应用）- 端口 5173/3000

---

## 🤔 为什么这样设计？

### 1. **开发调试便利性**

**Flask 和 WebSocket 在本地运行的优势：**
- ✅ **热重载**：代码修改后自动重启，无需重建 Docker 镜像
- ✅ **调试方便**：可以直接使用 IDE 断点调试
- ✅ **日志查看**：日志直接输出到本地文件，查看方便
- ✅ **快速迭代**：开发时频繁修改代码，本地运行响应更快

**如果放在 Docker 中：**
- ❌ 每次代码修改需要重建镜像或进入容器
- ❌ 调试困难，需要配置远程调试
- ❌ 日志查看需要 `docker logs` 命令
- ❌ 开发效率降低

### 2. **环境隔离**

**Docker 中运行基础设施：**
- ✅ **MySQL、Redis**：版本固定，环境一致
- ✅ **数据持久化**：使用 Docker Volume，数据安全
- ✅ **依赖隔离**：不影响本地系统环境
- ✅ **一键部署**：生产环境可以直接使用相同的 Docker Compose 配置

**本地运行应用服务：**
- ✅ **使用 Conda 环境**：Python 依赖隔离，不影响系统 Python
- ✅ **灵活配置**：可以快速切换不同版本的依赖
- ✅ **开发工具集成**：IDE、调试器等工具可以直接使用

### 3. **性能考虑**

- **数据库和缓存**：Docker 中运行，资源隔离，性能稳定
- **应用服务**：本地运行，减少网络开销，响应更快

## 🔧 配置选项

### 使用 Docker 中的 Celery（可选）

如果希望 Celery 也在 Docker 中运行，可以设置环境变量：

```bash
# 启动时使用 Docker Celery
USE_DOCKER_CELERY=true ./start_all.sh
```

或者在脚本中修改：
```bash
# 在 start_all.sh 中设置
USE_DOCKER_CELERY=true
```

### 只启动基础设施（推荐开发模式）

```bash
# 只启动 MySQL 和 Redis
cd stock_ai_trading
docker compose up -d mysql redis

# 其他服务在本地 Conda 环境中运行
conda activate stock_trading
python run_flask.py --host 0.0.0.0 --port 5000 &
python start_websocket.py &
celery -A app.tasks.celery_app worker --loglevel=info &
celery -A app.tasks.celery_app beat --loglevel=info &
```

## 🎯 最佳实践

### 开发环境（当前配置）
- ✅ MySQL、Redis 在 Docker 中
- ✅ Flask、WebSocket、Celery 在本地 Conda 环境中
- ✅ 前端在本地运行
- **优势**：开发调试方便，快速迭代

### 生产环境（建议）
- ✅ 所有服务都在 Docker 中
- ✅ 使用 Docker Compose 统一管理
- ✅ 配置健康检查和自动重启
- **优势**：环境一致，易于部署和维护

## 📝 注意事项

1. **端口冲突**：
   - Docker 中的 `app` 服务配置的是 FastAPI（端口 8000），但实际使用的是 Flask（端口 5000）
   - 如果 Docker 中的 `app` 服务启动，不会与 Flask 冲突

2. **Celery 重复启动**：
   - 脚本会检查 Docker 中是否已运行 Celery
   - 如果已运行，不会重复启动
   - 默认在本地运行，便于查看日志和调试

3. **环境变量**：
   - 本地运行的服务需要正确配置 `.env` 文件
   - 数据库连接地址应为 `localhost:3306`（不是 Docker 服务名）

---

## 🔄 迁移到完全 Docker 化（可选）

如果希望所有服务都在 Docker 中运行，需要：

1. **修改 docker-compose.yml**：
   - 添加 Flask 服务（端口 5000）
   - 添加 WebSocket 服务（端口 8765）
   - 配置正确的启动命令

2. **创建 Dockerfile**：
   - 安装 Conda 环境
   - 安装项目依赖
   - 配置启动脚本

3. **更新启动脚本**：
   - 只启动 Docker Compose
   - 不再需要本地 Python 服务

**但这样会失去开发调试的便利性，建议保持当前混合架构。**

---

## 💡 总结

当前架构是**开发友好的混合架构**：
- **基础设施**（MySQL、Redis）在 Docker 中，稳定可靠
- **应用服务**（Flask、WebSocket、Celery）在本地，便于开发调试
- **前端**在本地，支持热重载

这种设计在开发效率和环境一致性之间取得了很好的平衡。
