## 二、核心修改内容

### 2.1 JWT Token优化

**修改文件：**
- `stock_ai_trading/app/config/config.py`
- `stock_ai_trading/app/middleware/auth.py`
- `stock_ai_trading/app/main.py`

**具体改动：**
1. Token过期时间延长
   ```python
   JWT_ACCESS_TOKEN_EXPIRES = timedelta(hours=24)  # 从1小时改为24小时
   JWT_REFRESH_TOKEN_EXPIRES = timedelta(days=90)   # 从30天改为90天
   ```

2. 实现自动续期机制
   - 在 `auth.py` 的 `authenticate_request()` 中检查token剩余时间
   - 剩余时间 < 6小时时，自动生成新token
   - 通过响应头 `X-New-Token` 返回新token给前端

3. 添加 `after_request` 钩子
   - 在 `main.py` 中实现请求后处理
   - 将新生成的token添加到响应头

**优势：**
- ✅ 用户体验大幅提升（24小时内无需重新登录）
- ✅ 安全性保持（token仍有过期时间）
- ✅ 无感续期（前端自动获取新token）
- ✅ 后端实现简洁（middleware + after_request）

## 四、同步服务修复（16:30-17:00）

### 4.1 工作概述
在日线行情同步功能修复成功后，检查并修复了其他同步服务中存在的类似问题，包括日期格式转换和NaN值处理。

### 4.2 发现的问题
1. **日期格式转换问题**：
   - `daily_basic_sync.py`、`limit_price_sync.py` 等服务的 `_get_trade_dates` 方法返回的日期可能是 `datetime.date` 对象
   - 直接用于 Tushare API 调用和日志记录时会导致序列化错误

2. **NaN值处理问题**：
   - `daily_basic_sync.py` 在保存数据时，DataFrame 中的 NaN 值无法直接插入 MySQL
   - 导致 `nan can not be used with MySQL` 错误

3. **日期字段格式不一致**：
   - `adj_factor_sync.py`、`suspend_sync.py` 等服务的日期字段也需要统一转换为 YYYYMMDD 字符串格式

### 4.3 修复内容

#### 修复文件
- `stock_ai_trading/app/services/sync_services/daily_basic_sync.py`
- `stock_ai_trading/app/services/sync_services/limit_price_sync.py`
- `stock_ai_trading/app/services/sync_services/adj_factor_sync.py`
- `stock_ai_trading/app/services/sync_services/suspend_sync.py`

#### 主要改动
1. **统一日期格式转换**：在 `_get_trade_dates` 和同步循环中，确保所有日期都转换为 YYYYMMDD 字符串格式
2. **添加NaN值处理**：在 `_save_daily_basic` 方法中添加 `clean_value` 函数，将 NaN 值转换为 None
3. **增强日期验证**：添加日期格式验证，确保日期长度为8位且为数字

### 4.4 测试结果
- ✅ 每日指标同步：修复后正常运行，无 NaN 错误，进度正常（4/11，36%）
- ✅ 日期格式转换：所有日期统一为 YYYYMMDD 格式
- ✅ 服务重启：Flask 服务正常重启，修复生效
