## 遇到的问题及解决方案

### 1. 字段名不匹配
- **问题**：代码中使用`symbol`，但数据库字段是`stock_code`
- **解决**：统一使用`stock_code`

### 2. Decimal类型错误
- **问题**：数据库字段是Decimal类型，但代码中使用float进行运算
- **解决**：将所有价格和金额转换为Decimal类型

### 3. 持仓创建失败
- **问题**：`stock_name`字段不能为空
- **解决**：在创建持仓时从订单中获取`stock_name`

### 4. 事务回滚问题
- **问题**：多个订单在同一事务中，一个失败导致全部回滚
- **解决**：每个订单使用独立的数据库会话和事务

### 5. 持仓API Session绑定问题
- **问题**：持仓对象脱离Session后无法调用`to_dict()`
- **解决**：在关闭Session前转换为字典

### 6. 交易时间限制
- **问题**：非交易时间无法下单
- **影响**：晚上无法测试卖出功能
- **解决方案**：
  - 方案1：在交易时间内测试
  - 方案2：临时关闭交易时间检查（仅用于测试）
  - 方案3：使用手动撮合脚本（不受交易时间限制）

## 技术要点

### Decimal类型处理
在Python中处理数据库的Decimal字段时，需要注意：
```python
from decimal import Decimal

# 正确的方式
price = Decimal(str(float_value))
commission = amount * Decimal('0.0003')

# 错误的方式（会导致类型错误）
commission = amount * 0.0003  # TypeError
```

### 数据库事务管理
对于批量处理的场景，建议每个操作使用独立的事务：
```python
for item in items:
    db = next(get_db())
    try:
        # 处理单个项目
        process_item(db, item)
        db.commit()
    except Exception as e:
        db.rollback()
        logger.error(f"处理失败: {e}")
    finally:
        db.close()
```

### Session绑定问题
ORM对象脱离Session后无法访问关联属性：
```python
# 错误的方式
positions = query.all()
db.close()
for pos in positions:
    pos.to_dict()  # 错误：对象已脱离Session

# 正确的方式
positions = query.all()
positions_data = [pos.to_dict() for pos in positions]
db.close()
return positions_data
```
