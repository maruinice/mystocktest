## 1. Enum类型兼容性问题
**问题描述**: 
在使用SQLAlchemy Enum类型时，数据库存储的是字符串值，但Python代码中期望的是Enum对象。在序列化和反序列化过程中，经常出现 `'str' object has no attribute 'value'` 或类型不匹配错误。

**解决方案**:
- 将 `agent_models.py` 中的所有 `Enum` 列类型修改为 `String`。
- 在 `agent_service.py` 和 `multi_agent_engine.py` 中，移除所有将字符串转换为Enum对象的操作，直接使用字符串进行传递和存储。
- 在API层，确保接收和返回的都是字符串值。

## 2. 数据库非空约束错误
**问题描述**:
执行单股分析时，报错 `Column 'scheme_id' cannot be null`。这是因为 `stock_selection_results` 表设计时要求 `scheme_id` 非空，但单股分析（非方案执行）时没有关联的 `scheme_id`。

**解决方案**:
- 修改数据库表结构，将 `scheme_id` 列改为允许 NULL。
- 执行 SQL: `ALTER TABLE stock_selection_results MODIFY COLUMN scheme_id VARCHAR(50) NULL COMMENT '方案ID';`

- 当捕获到LLM调用异常时，生成模拟的分析结果（评分、推荐、分析内容等），确保流程能够继续执行并生成分析记录。

## 4. 数据同步管理页面“最后更新时间”不显示

**问题描述**：
用户反馈“数据同步管理”页面中，财务指标、行业分类、审计意见等面板点击同步后不显示“最后更新时间”。

**原因分析**：
1.  **行业分类**：数据库 `industry_classification` 表中 `in_date` 字段为 NULL，导致无法获取最后更新时间。同步服务未将 Tushare 返回的 `in_date` 写入数据库。
2.  **通用逻辑**：`SyncManager` 中的 `get_data_statistics` 方法对某些表的日期字段映射不准确，且仅获取 `MAX(date)`，无法反映数据的完整时间范围。
3.  **前端显示**：前端仅显示 `last_sync_date`，对于历史数据补全的场景（如审计意见），用户更关心数据的覆盖范围。

**解决方案**：
1.  **后端改造**：
    - 修改 `BaseSyncService`，添加 `get_sync_date_range` 方法，同时获取 `MIN(date)` 和 `MAX(date)`。
    - 修改 `SyncManager`，正确映射各表的日期字段（如 `industry_classification` 使用 `in_date`，`suspend_info` 使用 `suspend_date`），并返回 `min_date` 和 `max_date`。
    - 修复 `IndustryClassificationSyncService`，在插入数据时正确保存 `in_date` 和 `out_date`。
2.  **前端优化**：
    - 将卡片上的“最后更新”改为“数据范围”，显示数据的起始和结束日期。

## 5. 财务指标和审计意见同步不支持增量和历史补全

**问题描述**：
用户希望支持增量更新（向后同步最新数据）和历史补全（向前同步更早数据），且目前的同步逻辑只插入了极少数硬编码的字段，导致数据严重丢失。

**解决方案**：
1.  **同步逻辑升级**：
    - 修改 `FinancialIndicatorSyncService` 和 `AuditOpinionSyncService` 的 `sync` 方法，增加 `direction` ('forward'/'backward') 和 `days` 参数。
    - 实现基于每只股票的增量逻辑：
        - **向后更新**：从数据库中该股票的 `max_date + 1` 同步到今天。
        - **向前追溯**：从数据库中该股票的 `min_date - days` 同步到 `min_date - 1`。
2.  **数据完整性修复**：
    - 修改上述服务的底层同步方法，使用 `pandas` 和动态 SQL 构建，将 Tushare API 返回的所有字段完整插入数据库，解决了字段丢失问题。
3.  **前端交互**：
    - 在同步对话框中添加“同步方向”选择（向后更新/向前追溯）和“回溯天数”输入框。
