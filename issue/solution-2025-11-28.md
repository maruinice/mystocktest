## 1. 交易日历向前追溯不生效

**问题描述**:
在数据同步管理页面，交易日历点击"向前追溯（历史）"并输入 3650 天（十年），同步完成后仍显示 2022/11/01 至 2025/11/28，没有向前追溯。

**原因分析**:
`TradeCalSyncService`、`LimitPriceSyncService` 和 `SuspendSyncService` 的 `sync` 方法没有支持 `direction` 和 `days` 参数，导致前端传递的参数被忽略。

**解决方案**:
1.  修改 `trade_cal_sync.py`，添加 `direction` 和 `days` 参数支持。
2.  修改 `limit_price_sync.py`，添加 `direction` 和 `days` 参数支持。
3.  修改 `suspend_sync.py`，添加 `direction` 和 `days` 参数支持。
4.  实现向前追溯逻辑：从 `min_date - days` 到 `min_date - 1`。
5.  实现向后更新逻辑：从 `max_date + 1` 到今天。

## 2. 浮动盈亏百分比计算错误

**问题描述**:
投资组合管理页面中的"持仓明细"面板内的浮动盈亏百分比显示错误：¥-8.00，-68.38%（应该是 -0.68%）。

**原因分析**:
后端 `trade_service_db.py` 计算 `profit_loss_pct` 时已经乘以了 100（返回的是百分比值，如 -0.6838 表示 -0.6838%），但前端 `Portfolio.vue` 在显示时又乘以了 100，导致显示为 -68.38%。

**解决方案**:
修改 `Portfolio.vue` 第 152 行，移除 `* 100`：
```javascript
// 修改前
{{ ((row.profit_loss_pct || 0) * 100).toFixed(2) }}%
// 修改后
{{ (row.profit_loss_pct || 0).toFixed(2) }}%
```

## 6. 涨跌停价格同步显示0条记录但数据库有数据

**问题描述**:
在数据管理模块> 数据同步菜单中对"涨跌停价格"进行"向后更新（最新）"同步时，出现显示和数据库中都没有数据的情况：
- 已同步 16/16 个交易日，共 0 条记录
- 数据条数: 241800
- 数据范围: 2023/01/30 至 2025/11/06

**原因分析**:
1. 字段访问不安全：代码中使用 `row['ts_code']` 和 `row['trade_date']` 直接访问，如果Tushare API返回的字段名不匹配会抛出KeyError，异常被捕获后继续执行，导致保存失败但无提示。
2. 缺少调试信息：没有记录DataFrame的列名和数据条数，难以诊断问题。
3. 可能的字段名不匹配：Tushare API返回的字段名可能与代码期望的不一致。

**解决方案**:
1. 添加调试日志：在同步过程中记录DataFrame的列名、数据条数，以及每个日期的同步情况。
2. 使用安全的字段访问：改用 `row.get()` 方法，支持大小写变体（如 `ts_code` 和 `TS_CODE`）。
3. 添加字段验证：在保存前检查必需字段是否存在，如果缺失则记录错误并返回。
4. 改进错误处理：记录详细的错误信息，包括失败的行数和具体错误原因。
5. 日期格式处理：统一处理不同格式的日期数据（字符串YYYYMMDD、日期对象等）。

**修改文件**:
- `stock_ai_trading/app/services/sync_services/limit_price_sync.py`

**主要修改点**:
1. 在 `sync` 方法中添加调试日志，记录每个日期获取的数据条数和字段名
2. 在 `_save_limit_price_data` 方法中：
   - 添加DataFrame列名和数据条数的日志
   - 检查必需字段是否存在
   - 使用安全的字段访问方式（`row.get()`）
   - 添加错误统计和详细错误日志
   - **关键修复1**：将trade_date从字符串格式转换为DATE类型（数据库表中trade_date是DATE类型，不是VARCHAR）
   - **关键修复2**：移除不存在的`pre_close`字段，使用实际存在的字段（`close`、`up_limit`、`down_limit`）
   - 移除错误的CREATE TABLE语句（表已存在，且结构不同）

**实际表结构**:
```sql
CREATE TABLE `limit_prices` (
  `id` int NOT NULL AUTO_INCREMENT,
  `ts_code` varchar(20) NOT NULL,
  `trade_date` date NOT NULL,
  `up_limit` float NULL,
  `down_limit` float NULL,
  `close` float NULL,
  `pct_chg` float NULL,
  `is_limit_up` tinyint(1) NULL,
  `is_limit_down` tinyint(1) NULL,
  `created_at` datetime NULL,
  PRIMARY KEY (`id`),
  UNIQUE INDEX `idx_ts_code_date`(`ts_code`, `trade_date`)
)
```

**错误原因**:
1. 代码尝试插入`pre_close`字段，但表中没有该字段
2. 代码使用VARCHAR格式的trade_date，但表中是DATE类型

**测试方法**:
1. 通过浏览器访问数据管理模块 > 数据同步
2. 选择"涨跌停价格"，点击"向后更新（最新）"
3. 观察同步进度和日志输出
4. 检查数据库中是否有新数据保存
5. 查看浏览器控制台和服务器日志，确认是否有字段名不匹配的错误
