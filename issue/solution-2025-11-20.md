## 问题1：数据分析页面报错

### 问题描述
点击"数据分析"页面的"分析"按钮后，弹出错误提示：
- "请求的资源不存在"
- "数据加载失败"

### 原因分析
前端调用的财务数据API路由为 `/api/data/financial/{symbol}`，但后端只实现了 `/api/data/stocks/<code>/financials` 路由，导致404错误。

### 解决方案
在 `stock_ai_trading/app/api/data_api.py` 中添加新的路由以匹配前端请求：

```python
@data_bp.route('/financial/<string:symbol>', methods=['GET'])
@require_auth
def get_financial_data_api(symbol: str):
    """获取股票财务数据（前端专用API）"""
    try:
        # 验证股票代码
        if not symbol:
            return jsonify({
                "success": False,
                "error": "股票代码不能为空"
            }), 400
        
        # 获取查询参数
        report_type = request.args.get('report_type', 'annual')
        year = request.args.get('year')
        limit = int(request.args.get('limit', 5))
        
        # 获取财务数据
        financials = data_service.get_stock_financials(
            code=symbol,
            report_type=report_type,
            year=year,
            limit=limit
        )
        
        return jsonify({
            "success": True,
            "data": financials
        })
        
    except Exception as e:
        logger.error(f"获取财务数据失败: {str(e)}")
        return jsonify({
            "success": False,
            "error": "获取财务数据失败"
        }), 500
```

### 验证结果
✅ **已解决** - 数据分析页面不再报错，财务数据API正常响应（返回空数据是因为数据库中暂无财务数据，但API路由已正常工作）

## 问题2：股票搜索功能数据不匹配

### 问题描述
- 数据同步页面显示"日线行情"有4376288条数据
- 但交易中心的股票搜索无法搜索到数据
- 怀疑数据同步的表和查询的表不是同一个

### 原因分析
1. **表结构混乱**：系统中存在多个行情相关的表：
   - `stock_quotes`：空表（0条记录），models中定义但未使用
   - `daily_quotes`：125条记录，用于选股功能
   - `daily_history`：4119346条记录，**这是主要的行情数据表**

2. **API查询错误**：`app/services/data_service.py` 中的 `get_stock_quotes()` 方法查询的是 `daily_quotes` 表，而大量数据实际存储在 `daily_history` 表中。

### 解决方案
修改 `stock_ai_trading/app/services/data_service.py` 中的查询表名：

```python
# 第169行：修改前
FROM daily_quotes

# 修改后
FROM daily_history
```

同样修改第248行的查询：

```python
# 第248行：修改前
FROM daily_quotes

# 修改后
FROM daily_history
```

### 验证结果
✅ **已解决** - 股票搜索功能正常工作，输入"000001"能够搜索到"000001.SZ 平安银行 ¥11.80 1.81%"

## 2025-11-20 16:30 - 同步服务日期格式和字段名修复

### 问题描述
在修复日线行情同步功能后，发现其他同步服务也存在类似问题：
1. **日期格式转换问题**：`daily_basic_sync.py`、`limit_price_sync.py` 等服务的 `_get_trade_dates` 方法返回的日期可能是 `datetime.date` 对象，但直接用于 Tushare API 调用和日志记录时会导致序列化错误
2. **NaN值处理问题**：`daily_basic_sync.py` 在保存数据时，DataFrame 中的 NaN 值无法直接插入 MySQL，导致 `nan can not be used with MySQL` 错误
3. **日期字段格式不一致**：`adj_factor_sync.py`、`suspend_sync.py` 等服务的日期字段也需要统一转换为 YYYYMMDD 字符串格式

### 解决方案

#### 1. 修复日期格式转换（daily_basic_sync.py, limit_price_sync.py）
在 `_get_trade_dates` 方法中，确保返回的日期都是 YYYYMMDD 字符串格式：
```python
trade_dates = []
for row in result:
    date_val = row[0]
    # 确保日期格式为YYYYMMDD字符串
    if hasattr(date_val, 'strftime'):
        trade_dates.append(date_val.strftime('%Y%m%d'))
    elif isinstance(date_val, str):
        date_str = date_val.replace('-', '') if '-' in date_val else date_val
        trade_dates.append(date_str)
    else:
        date_str = str(date_val).replace('-', '')
        trade_dates.append(date_str)
```

在同步循环中，再次确保日期格式正确：
```python
for i, trade_date_raw in enumerate(trade_dates, 1):
    # 确保trade_date是字符串格式（YYYYMMDD）
    trade_date = trade_date_raw
    if not isinstance(trade_date, str):
        if hasattr(trade_date, 'strftime'):
            trade_date = trade_date.strftime('%Y%m%d')
        else:
            trade_date = str(trade_date).replace('-', '')
    elif '-' in trade_date:
        trade_date = trade_date.replace('-', '')
    
    # 验证日期格式
    if len(trade_date) != 8 or not trade_date.isdigit():
        logger.warning(f"日期格式不正确: {trade_date_raw} -> {trade_date}，跳过")
        continue
```

#### 2. 修复NaN值处理（daily_basic_sync.py）
在 `_save_daily_basic` 方法中，添加 `clean_value` 函数处理 NaN 值：
```python
# 处理NaN值，转换为None
def clean_value(val):
    if pd.isna(val) or val is None:
        return None
    return val

db.execute(insert_sql, {

    'turnover_rate': clean_value(row.get('turnover_rate')),
    # ... 其他字段也使用 clean_value
})
```

在保存数据时，确保日期字段格式正确：
